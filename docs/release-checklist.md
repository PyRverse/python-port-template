# Before the first scientific release

- Rename the distribution, import package, repository URLs, and examples.
- Define the scientific scope and acknowledge original authors and citations.
- Complete the provenance and license review for code, documentation, and data.
- Implement and review the method; remove or clearly separate template examples.
- Document supported options and known departures from upstream behavior.
- Generate reference fixtures with recorded environments and justified tolerances.
- Run tests, lint, formatting, type checks, build, and installed-wheel smoke tests.
- Inspect the distribution contents and confirm no private data or credentials.
- Record exact dependency versions and verify the supported Python matrix.
- Publish validation evidence and limitations before asserting parity.
- Choose a version, changelog, maintainers, and support policy appropriate to
  the actual project. Configure publishing separately and review its permissions.
