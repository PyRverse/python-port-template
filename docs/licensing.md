# Licensing and attribution

The MIT license in this repository covers the original scaffold. No upstream
R package code is included, and this is not a license decision for a future port.

Before adding an implementation, review the exact version of the upstream
package, its license files, notices, dependencies, bundled code, documentation,
and any data license. Record the evidence and review outcome in
[PROVENANCE.md](../PROVENANCE.md).

Copied or translated source may carry license and attribution requirements.
Do not treat a change of programming language as removing those requirements.
Retain required notices, identify modifications, and select a distribution
license compatible with all included material. Where rights or compatibility
are unclear, resolve the question with the rights holder or qualified advice
before including the material.

For an independent implementation, record the published specifications and
papers used, how the implementation was developed, whether upstream source was
consulted, and which code or data was reused. Do not label work "clean room"
without documenting the actual separation process. Attribution and citations
remain part of responsible scientific practice.

Useful starting points:

- [SPDX license list](https://spdx.org/licenses/)
- [GitHub: Licensing a repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

These steps support a recorded project decision; they do not promise legal
clearance for every method or jurisdiction.
